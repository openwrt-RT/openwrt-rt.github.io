认识设备包 ​

设备包是一个后缀为 .dcpkg 的 ZIP 文件。它向 BtRemix 声明：

  • 这台设备叫什么、如何识别；
  • 使用什么传输方式与帧格式；
  • 如何把字节帧映射成状态和动作；
  • 如何生成设备页面；
  • 是否需要调用宿主提供的第一方扩展。

设备包是可审查的数据，不是插件程序。包内不能携带 .dex、.so、.class、.jar、JavaScript 或其他可执行代码。

当前格式 ​

新包统一使用以下版本：

json
{
  "packageFormat": 1,
  "manifest": {
    "schemaVersion": 5,
    "runtimeApi": 1
  }
}

版本含义
packageFormat: 1外层 ZIP 与元数据格式
schemaVersion: 5定义 JSON 可使用的最新结构
runtimeApi: 1当前宿主运行时能力版本

schemaVersion: 5 不等于必须使用 segmented 协议。旧式单字节头尾协议仍可在 v5 中使用 codec: "framed"。

四条硬规则 ​

  1. package.json.id 必须等于 manifest.id。
  2. package.json.version 必须等于 manifest.version。
  3. 新包的 manifest.schemaVersion 写 5，不要从旧包复制 3 或 4 后零散追加字段。
  4. 包内只能有 JSON 文件和 assets/** 资源。

推荐编写顺序 ​

  1. 从包目录与容器建立最小骨架。
  2. 在 Manifest 与设备匹配中定义身份和匹配规则。
  3. 根据抓包在协议与事务中还原帧布局。
  4. 用状态、动作与界面暴露设备能力。
  5. 只在确有需要时加入程序与设备扩展。
  6. 按测试、安装与排错运行真实校验器并上机验证。

架构边界 ​

通用协议层、UI 和 Melody 不承载厂商语义。厂商差异应被隔离在第一方扩展中，并由应用组合根显式注册。

设备包可以声明所需能力，但不能提供扩展实现。扩展不能取得 Android Context、蓝牙句柄、UI、Melody 对象或设备包文件系统访问权；所有协议 I/O 都必须经过宿主受控接口。

从哪里复制

优先参考仓库中的 v5 样例：

  • samples/lab.static：静态事务、CRC、入站通知；
  • samples/lab.reactive：条件初始化、设备主动请求；
  • samples/lab.authenticated：受控第一方扩展调用。
  • samples/xiaomi.mma：RFCOMM、MMA 认证、电量与降噪；
  • samples/xiaomi.redmi_buds6：精确型号、RCSP TargetInfo、设备主动通知。

不要直接把旧格式样例的 schemaVersion 当成新包模板。

小米 / Redmi 的两条协议路径和对应设备包，见小米耳机协议。
