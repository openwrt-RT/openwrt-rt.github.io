程序与设备扩展 ​

v5 的流程使用受限 JSON 程序，不使用 JavaScript。

条件初始化 ​

json
{
  "op": "if",
  "condition": {
    "eq": [{"state": "authenticated"}, false]
  },
  "then": [
    {
      "op": "session.request",
      "request": "auth.challenge",
      "timeoutMs": 500,
      "into": "challenge"
    },
    {
      "op": "state.set",

表达式 ​

表达式含义
{"arg":"name"}动作参数
{"var":"name"}into 或 let 产生的变量
{"state":"key"}当前状态
{"hex":"01 A0 FF"}字节常量
{"at":[value,index]}读取指定字节
{"eq":[a,b]}比较
{"concat":[a,b]}拼接字节
{"len":value}字节长度
{"if":[condition,a,b]}条件表达式
{"map":{"value":value,"table":{...}}}值映射

常用操作 ​

op用途
let写局部变量
if条件分支
repeat重复 0–32 次
return返回动作结果
state.get / state.set读写状态
session.send发送受控帧
session.request执行事务并等待匹配响应
session.waitFor等待指定入站帧
session.onFrame动作期间注册临时入站处理器
extension.execute调用已声明的第一方扩展

新 RFCOMM 包使用 session.*。旧 ble.* 仅用于兼容旧 GATT 脚本。

程序默认执行超时 5 秒，单次最多 512 步、字节结果最多 4096 字节；解析时最多 256 个节点、嵌套最多 8 层。单个 timeoutMs 范围为 1–60000。

设备主动请求 ​

长期存在的入站流程应使用 triggers：

json
{
  "triggers": {
    "peer.request": {
      "matcher": {
        "command": 4096,
        "payloadPrefix": "01"
      },
      "program": [
        {
          "op": "session.send",
          "bytes": "A5 5A 00 90 03 03 00 02 13 CA"
        }
      ]
    }
  }
}

每个 trigger 必须有 matcher，并二选一使用 program 或 action。不同 trigger 的匹配范围不能重叠，否则包会被拒绝；一个入站帧最多触发一个 trigger。

session.onFrame 适合动作执行期间临时注册的处理器。固定长期流程应写成 trigger，避免生命周期难以追踪。

第一方扩展 ​

设备包只能声明扩展：

json
{
  "manifest": {
    "requires": ["session.extension", "session.request"],
    "extensions": [
      {
        "id": "example.auth",
        "apiVersion": 1,
        "entry": "default"
      }
    ]
  }
}

必须满足：

  • 扩展 ID 已在应用组合根显式注册；
  • apiVersion 与实现完全一致；
  • entry 由实现提供；
  • 调用入口与 manifest 声明一致；
  • 输入和输出各不超过 4096 字节。

扩展实现放在第一方隔离的 Gradle 模块中。扩展只能接收受控协议/会话 API，不能持有 Android Context、蓝牙句柄、UI、Melody 或设备包文件系统。

不可动态加载

设备包不能提供 .so、.dex、JavaScript 或动态类。所谓“扩展”只是对宿主已注册第一方实现的受控调用。
