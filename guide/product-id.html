Melody productId ​

melody.support.productId 是设备在 ColorOS Melody 白名单中的身份值。它不是蓝牙 MAC、不是 productType，也不是设备协议里的 command 或 opcode。

设备包可以声明官方 productId，也可以省略。省略时运行时仍会生成一个稳定的非零投影身份，因此没有官方 Melody 白名单值的第三方耳机也能进入投影流程。

声明位置 ​

json
{
  "melody": {
    "support": {
      "mode": "bridge",
      "name": "Example Buds",
      "brand": "Example",
      "productId": "3296",
      "productType": 1,
      "supportSpp": false,
      "suppressMelodyTransport": true
    }
  }
}

productId 可选；productType 是另一个字段，表示宿主的设备形态编码。不要用 productType 代替 productId。

输入形式与规范形式 ​

解析器可以读取十进制字符串、JSON 整数和 0x 前缀十六进制字符串，并把它规范化为十进制字符串：

输入规范化结果说明
"454672""454672"推荐写法
454672"454672"JSON 整数
"0x06F010""454672"明确的十六进制输入
"06F010""454672"含十六进制字母时可推断
"060412""60412"全数字 token 始终按十进制

虽然设备包可以使用上述输入形式，定义模型最终统一保存十进制字符串。为了可读性和避免进制歧义，发布包应直接写规范化十进制值。

有效范围是 0..0xFFFFFFFF。负数、空值、超过 32 位的值和非法十六进制都应被 validator 拒绝。0 虽然能通过数值解析，但宿主把它当作“未知”，发布包不应主动声明 0；省略字段会得到非零派生值。

从宿主导出复制原值时尤其要注意：06F010 这种含字母的 token 能被识别为十六进制，但 060412 这种全数字字符串会被当成十进制 60412。如果这是从十六进制 UI 复制的值，应写成 "0x060412"。

宿主的两种表示 ​

同一个值在 Melody 数据里可能出现两种形式：

位置形式示例
ears_whitelist.product_id、find_whitelist 参数十进制字符串454672
WhitelistConfigDTO.id、content.id大写、至少补足 6 位的十六进制06F010
DeviceInfo.mProductId非零整数454672

设备包只声明一种值；宿主在构造白名单和 DeviceInfo 时完成两种形式的转换。不要为了适配不同调用点重复声明两个 productId。

解析优先级 ​

构造完整 whitelist 投影时，productId 按以下顺序解析：

  1. 宿主实例已经提供的 productId；
  2. melody.support.productId；
  3. 内置白名单模板中的 id；
  4. 根据 MAC 派生的稳定 ID。

桥接支持信息没有模板层，因此使用：

text
Definition productId -> 稳定 MAC 派生 ID
1

模板中的 id 只用于模板自身的兜底，不应被当作目标耳机的真实产品身份。设备包应尽可能声明官方值，或者明确接受按实例派生的 ID。

省略 productId 时的行为 ​

当实例、Definition、模板都没有提供有效 productId 时，宿主生成 24 位稳定身份：

text
canonicalMac = MAC 去掉非字母数字字符并转大写
digest       = SHA-256("btremix-melody-product-id-v1:" + canonicalMac)
value        = bigEndian24(digest[0], digest[1], digest[2])
decimalId    = max(value, 1)
1
2
3
4

投影到 WhitelistConfigDTO.id 时，再格式化为 6 位大写十六进制。该实现保证：

  • 同一个规范化 MAC 在进程重启、应用重启和重装后得到相同值；
  • 不同 MAC 通常得到不同值；
  • 值始终非零，因为宿主把 0 当作未知；
  • 派生值不是厂商真实 productId。

域前缀 btremix-melody-product-id-v1: 用于隔离未来版本的派生算法。设备包作者不应自行复刻或硬编码这个计算结果；省略 productId 即可让运行时处理。

什么时候声明 ​

已知官方 Melody productId ​

按官方十进制值声明：

json
{
  "productId": "454672"
}
1
2
3

这适合已确认该型号在目标 Melody 版本中使用固定产品身份的场景。型号、品牌和 productId 应同时核对，不要从另一款设备复制 ID 来“强行启用”界面。

没有官方值或无法确认 ​

省略字段：

json
{
  "support": {
    "mode": "bridge",
    "name": "Redmi Buds 6",
    "brand": "Redmi",
    "productType": 1
  }
}

宿主会为该配对实例生成稳定 ID。同一型号的不同物理设备会得到不同派生值；这是按实例投影的正常行为。

不要声明猜测值 ​

不要用以下方式伪造身份：

  • 把另一个型号的官方 productId 直接复制过来；
  • 用 Bluetooth manufacturer ID、service UUID 或协议 opcode 充当 productId；
  • 把六位十六进制 UI 值去掉 0x 后当作十进制；
  • 为了让白名单命中而硬编码某个 MAC 的派生值。

这些做法可能让设备使用错误的宿主能力表，排查时也很难区分“协议不工作”和“身份投影到了另一款设备”。

productId 不匹配时 ​

宿主可能用 OEM 回调中的 productId 查询白名单，而 BtRemix 使用的是 Definition ID 或 MAC 派生 ID。实现先按 productId 精确匹配；零命中时，再在托管设备中按规范化设备名做唯一匹配。

名称匹配分两步：

  1. 优先使用大小写不敏感的完整名称匹配；
  2. 没有唯一完整匹配时，才尝试双向包含匹配。

只有唯一候选才会被采用。两个同名设备同时受管时，不会让其中一个替另一个回答查询。因此精确型号包仍应使用足够具体的 manifest.matchers 和 support.name。

与协议命令的区别 ​

名称示例所属层
Melody productId454672 / 06F010宿主白名单与 DeviceInfo 身份
productType1设备形态
RFCOMM service UUID0000FD2D-...连接寻址
command / opcode0x02、0x50设备协议
configId0x000B某个协议命令内部的配置项

这些值不能互相替代。productId 正确不代表协议命令正确；协议帧能通也不代表 Melody 已投影到正确型号。

校验与排错 ​

检查定义：

bash
cd BtRemix
./gradlew :app:testDebugUnitTest --tests '*MelodySectionSchemaTest'
1
2

重点观察：

  • melody.support.productId 是否已被规范化；
  • 同一个型号的多台设备是否出现意外的共享或分裂 identity；
  • 宿主查询使用的是 MAC，还是 productId + deviceName；
  • 精确 productId 未命中时，设备名是否唯一；
  • Definition 修改后是否重新导入设备包并重建 projection。

完整 Melody 投影示例见状态、动作与界面；小米样例的 productId 取舍见小米耳机协议。
