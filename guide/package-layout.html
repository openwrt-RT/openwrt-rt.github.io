definition.json 可以改名，但 package.json.entry 必须指向实际路径。

package.json ​

json
{
  "packageFormat": 1,
  "id": "example.buds",
  "version": "1.0.0",
  "entry": "definition.json"
}

字段要求
packageFormat整数 1
id[A-Za-z0-9][A-Za-z0-9._-]*，且等于 manifest.id
version非空，且等于 manifest.version
entry包内真实存在的 JSON 路径

安装后，文件按包 ID 保存为：

text
files/device-packages/example.buds.dcpkg
1

原始 ZIP 文件名不决定包 ID。发布更新时必须提高版本，再重新导入。

容器限制 ​

项目限制
压缩包大小最大 10 MiB
解压后大小最大 25 MiB
条目数量最多 100
单文件大小最大 5 MiB
允许的扩展名/路径*.json、assets/**

同时禁止：

  • 绝对路径；
  • .. 路径段；
  • 反斜杠；
  • 空路径段和盘符；
  • 重复 ZIP 条目；
  • 任何可执行文件或动态代码。

根目录可以有多个 JSON 文件，但非 JSON 资源必须放在 assets/ 下。

打包 ​

在包含 package.json 和 definition.json 的目录中生成 ZIP，再把扩展名改为 .dcpkg。打包后先检查内容：

bash
unzip -l example.dcpkg
unzip -p example.dcpkg package.json
unzip -p example.dcpkg definition.json | head

常见误打包

不要选中外层文件夹再压缩，否则 package.json 会落在 ZIP 子目录中，宿主无法从根路径读取。
